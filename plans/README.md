modules) against commit `519714f`. Godot/GDScript project — plans use

## Recommended execution order

1. **001** and **002** first — both are tiny, single-file, independent fixes
   inside `scenes/home/home.gd`. No dependency on anything else; do these
   before touching `home.gd` again in 003/004/005 to keep diffs small and
   easy to review individually.
2. **003** next — the highest-leverage plan (touches every module). It adds
   the `SceneTransition` autoload and rewires all 19 navigation call sites,
   including several in `home.gd`. Doing this after 001/002 avoids
   interleaving unrelated edits to the same file in one diff.
3. **004** after 003 — also touches most of the same files as 003 (adding
   `PressFeedback.attach(...)` calls near the same `_ready()`/button-creation
   code that 003's navigation rewiring sits in). Doing 003 first means 004's
   insertion points ("alongside the existing `.pressed.connect(...)` line")
   are being read against already-updated files, reducing merge friction
   between the two plans.
4. **005** last — isolated to `home.gd`'s `_refresh_quests`, independent of
   001/002/003/004, but scheduled last since it restructures a function that
   003 and 004 also add code near (003 doesn't touch `_refresh_quests`
   itself; 004 adds one `PressFeedback.attach(log_button)` call inside it —
   do 004 before 005 so 005's "move the loop body verbatim" step is moving
   code that already includes 004's line).

## Dependencies between plans

- **003 → 004**: not a hard dependency (004 would still apply cleanly to
  the pre-003 code), but doing 003 first avoids two plans editing the same
  `_ready()` blocks in parallel diffs.
- **004 → 005**: 004 adds a line inside the loop body that 005 moves
  verbatim into `_rebuild_quest_cards`. Apply 004 before 005 so that line
  moves along with the rest of the loop body instead of needing a manual
  merge afterward.
- **001, 002**: no dependencies on any other plan or each other.

## Notes

- All five plans were vetted against the actual code at commit `519714f`
  before being written — if the repo has moved on since, each plan's
  "Boundaries" section instructs the executor to stop and report rather than
  guess when cited line numbers don't match.
- Scope was deliberately kept to *motion only* per the request that started
  this audit. A few structural (non-motion) issues were noticed along the
  way and are intentionally **not** in any plan here — most notably, quest
  cards are identified by full teardown/rebuild rather than a stable
  per-quest key, which 005 papers over with a crossfade rather than fixing
  at the root. That's a legitimate follow-up but a data-model change, not an
  animation fix.
